# 1.2.0 — каталог готових патернів APEX

[English](release-notes.md) | Українська

## Зміни — 2026-09-24

- Офлайн-пошук **58 готових патернів** через `corpus: "patterns"` та сталі ID `pattern:`. Для адаптації доступні **84 рецепти**: 69 мають перевірені компілятором реалізації, 15 зберігають явні причини unresolved.
- Перевірено **150 сторінок джерел і 818 змістовних варіантів** Universal Theme Reference та Oracle APEX UX Pattern Catalog. Записи покриття прив’язують рішення щодо кожної сторінки до точного хешу джерела; відсутні чи застарілі огляди, невідомі source anchors і патерни без згадок у них блокують збірку.
- Новий skill `$apexrest-pattern-catalog` додає патерни з визначених застосунків APEX. Він захоплює факти джерел лише читанням, зберігає сталі ID джерел, керує підготовкою власних рецептів і перевіркою змінених залежностей перед пакуванням.
- Пошук англійською й українською через наявні MCP-довідники та CLI. Великі записи покриття читаються частинами зі збереженням усіх посилань. Пошук у встановленому каталозі працює офлайн без проєкту чи з’єднання Oracle.
- Збережено наявний каталог компонентів зі **109 сімействами та 138 готовими рецептами**, типовий `corpus: "apexlang"`, ID довідки Oracle, операції SQLcl/ORDS і запобіжники розгортання. Плагін тепер надає **18 MCP-інструментів і 13 skills** у поточній розмові Codex.

Перегляньте [список компонентів і приклади Universal Theme](https://apex.oracle.com/ut), потім скористайтеся [посібником каталогу патернів](pattern-catalog.uk.md) або [посібником каталогу компонентів](component-catalog.uk.md).

## Перевірки та межі

[Поточні докази каталогу](evidence/pattern-catalog-local.json) фіксують 69 справжніх офлайн-перевірок компілятором SQLcl без попереджень із прив’язкою до точних вхідних файлів scaffold і рецептів. Локальні перевірки пройшли: 187 модульних тестів, 57 контрактних тестів, 26 тестів інсталяторів і 25 пакувальних тестів, а також детерміновані каталоги, двомовна документація, синхронізація плагіна й офлайн CLI/MCP після перенесення. [Попередні докази компонентів](evidence/component-catalog-local.json) зберігають 138 підтверджень компіляції без змін.

`ready` означає повний оголошений набір локальних залежностей із відповідними доказами компілятора. Виконання SQL prerequisites, імпорт, автентифікований браузер і виконання моделлю нативного хоста лишаються окремими й для цієї роботи не виконувалися. Обсяг відповідей вимірюється байтами UTF-8, а не оплачуваними токенами.

## Розповсюдження

`apexrest@1.2.0` підготовлено до дозволеної публікації як npm `latest`; перевірки цілісності в реєстрі й чистого встановлення ще очікуються. [Запис попередньої публікації 1.1.0](evidence/npm-110-publication.json) залишається історичним доказом і не підтверджує 1.2.0.

Публікація npm відокремлена від вимкненого захищеного publisher артефактів GitHub. Вона не означає підписані GitHub-артефакти, Git-тег, розгортання сайту чи повну кваліфікацію платформ/Oracle. Оновлення активного кешу плагіна Codex і нова розмова для завантаження його інструментів — окремі дії встановлення.

Ці межі відстежують [стан реалізації](implementation-status.uk.md), [матриця приймання](acceptance.json), [налаштування публікації](publishing.uk.md) та [відкриті перевірки](next-actions.uk.md).
