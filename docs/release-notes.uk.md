# 1.1.0 — каталог готових компонентів

[English](release-notes.md) | Українська

## Зміни — 2026-09-24

- Офлайн-пошук серед **109 сімейств компонентів**, параметри з контекстом і **138 перевірених компілятором рецептів APEXlang** для адаптації. Один непідтриманий рецепт шаблонного компонента залишається видимим із причиною unresolved.
- Селектор `corpus: "components"` у наявних MCP-довідниках і CLI. Чинні IDs довідки Oracle та типова поведінка `corpus: "apexlang"` зберігають сумісність.
- Окремі контракти нативних регіонів, шаблонів звітів/списків, шаблонних компонентів, полів, кнопок і сторінок. Збережено облік джерел, англійські/українські пошукові назви, defaults і залежності параметрів, описи під UPL та стабільні IDs із hashes вмісту.
- Каталог постачається для офлайн-роботи без проєкту чи з’єднання Oracle. Рецепти містять синтетичні дані та явні контракти prerequisites; процес отримання джерел для розробника виконує лише читання й відокремлений від пошуку.
- Збережено роботу в поточній сесії Codex, 18 MCP-інструментів, 12 skills, операції SQLcl/ORDS, запобіжники розгортання та чинні межі дозволів.

Перегляньте [список компонентів і приклади Universal Theme](https://apex.oracle.com/ut), потім скористайтеся [посібником каталогу](component-catalog.uk.md).

## Перевірки та межі

[Докази каталогу](evidence/component-catalog-local.json) фіксують 138 справжніх офлайн-перевірок компілятором Oracle без попереджень із прив’язкою до точних файлів scaffold і рецептів. Також записано 181 модульний тест, 42 контрактні тести, 19 пакувальних тестів, детерміновані перевірки каталогу, двомовну документацію, синхронізацію плагіна й офлайн-пошук через CLI/MCP після перенесення пакета. Це підтверджує зазначену локальну поведінку; виконання SQL prerequisites, імпорт, автентифікований браузер і виконання моделлю нативного хоста лишаються окремими й для цієї роботи не виконувалися.

`ready` означає повний оголошений набір локальних залежностей із відповідними доказами компілятора. Це не означає імпорт або перевірку рецепта на живій БД. Обсяг відповідей вимірюється байтами UTF-8, а не оплачуваними токенами.

## Розповсюдження

`apexrest@1.1.0` опубліковано як npm `latest`. [Запис публікації 1.1.0](evidence/npm-110-publication.json) підтверджує цілісність пакета в реєстрі та чисті локальне й глобальне встановлення для коміту джерел `284b554d762545e76b64913b7f34c45c44f01833`. [CI випуску](https://github.com/apexrest-dev/apexrest-codex/actions/runs/35987234098) успішно завершився на Ubuntu, macOS і Windows. Попередню публікацію 1.0.0 збережено окремо нижче.

Публікація npm відокремлена від вимкненого захищеного publisher артефактів GitHub. Вона не означає підписані GitHub-артефакти, Git-тег, розгортання сайту чи повну кваліфікацію платформ/Oracle. Оновлення активного кешу плагіна Codex і нова розмова для завантаження його інструментів — окремі дії встановлення.

Ці межі відстежують [стан реалізації](implementation-status.uk.md), [матриця приймання](acceptance.json), [налаштування публікації](publishing.uk.md) та [відкриті перевірки](next-actions.uk.md).
