# Стан реалізації — бета 0.1.0-beta.1

[English](implementation-status.md) | Українська

Початкова специфікація збережена без змін. Це робочий код і придатна до встановлення бета, а не продукт, кваліфікований як стабільний. [acceptance.json](acceptance.json) відокремлює реалізацію, перевірку, докази та блокери для кожного критерію A01–A28.

## Сайт у метаданих плагіна

Метадані плагіна задають `interface.websiteURL` зі значенням `https://apex.rest` для сторінки відомостей у Codex. Згенерований і встановлений нативні маніфести містять те саме значення. 2026-09-12 Codex CLI підтвердив, що плагін із локального marketplace репозиторію встановлений і ввімкнений; хеші всіх 198 файлів установленого пакета збіглися, а встановлений CLI підтвердив його валідність. Візуальне підтвердження поля Website залишається недоступним, оскільки інструмент керування комп’ютером не дозволяє доступ до застосунку Codex. Ця обмежена перевірка встановлення не оновлює докази повного нативного життєвого циклу чи Oracle.

## Пошук APEXlang для Codex

[Оптимізація APEXlang](apexlang-optimization.uk.md) додає прямі маршрути компонентів, повні зафіксовані описи/шаблони Oracle, ранжований обмежений пошук, зіставлення версій, назви правил граматики та готовий пошуковий індекс. Дванадцять детермінованих випадків пошуку проходять. [Нативна перевірка](evidence/apexlang-codex.json) підтверджує виявлення й читання довідки в ізольованому профілі Codex 0.154.0 macOS arm64. [Перевірка компілятора](evidence/apexlang-compiler.json) підтверджує три локальні композиції застосунків із незмінним MMD. Ці перевірки не встановлюють частоту успіху генерації моделлю, результати SQL із підключенням чи поведінку застосунку в браузері. Збирання тепер випускає лише нативний пакет Codex; наявні інсталяції та публікація не змінені.

## Поточні перевірки й прив’язка до коду

[evidence/local-checks.json](evidence/local-checks.json) записує останній зведений локальний запуск: версію Node, digest коду, коди завершення, тривалості й хеші журналів. Приватні консольні журнали залишаються в `.apexrest/check-logs/`. Набір містить 64 модульні, 14 інсталяційних, шість контрактних CLI/MCP і 12 пакувальних тестів. Модульні й інсталяційні фікстури не є інтеграційними доказами Oracle.

Пакет репозиторію перевіряється через `npm run plugin:check`: актуальність коду, хеш кожного файла, відповідність нативного marketplace і збіг зі свіжою збіркою. `npm run plugin:sync` регенерує його після змін джерел. Ці перевірки виконуються в CI Linux, macOS і Windows.

Окремий [звіт двомовної документації](evidence/documentation-bilingual.json) записує 36 англійських/українських пар документів, 28 згенерованих маршрутів і 13 успішних пакувальних тестів, включно з мовною навігацією та ізоляцією пошукових індексів. `npm run docs:check` перевіряє наявність відповідників, однаковість виконуваних прикладів, структуру заголовків і локальні посилання. Спостереження вбудованого браузера покривають перемикання мов, пошук, діаграми й вузький макет; вони записані окремо та не оновлюють доказів Oracle чи нативного хоста.

[Звіт hosted CI](evidence/repository-ci.json) записує точний коміт і digest коду. Hosted тести перевіряють локальний код, пакування та генерацію сайту; вони не засвідчують нативного життєвого циклу Codex чи операцій підключеного Oracle. Попередні звіти зберігають початкові digest і потребують оновлення перед використанням для стабільного випуску.

## Докази нативного встановлення й компілятора

[Smoke-звіт встановлення з репозиторію](evidence/native-repository.json) фіксує джерело встановлення, платформу й версії виконання, вісім навичок, 14 підключених інструментів, обмежений пошук довідки, doctor та огляд проєкту поза кешем плагіна. Це перевірка нативного хоста лише для читання без імпорту Oracle.

[Докази нативного життєвого циклу](evidence/native-codex-compat.json) окремо записують попередній ізольований цикл хоста та реальні генерацію/валідацію SQLcl. [Докази компілятора](evidence/oracle-local.json) покривають blank-app і customer-CRM. [Докази керованого setup](evidence/setup-local.json) покривають попереднє локальне налаштування й повторне offline встановлення. Digest коду кожного звіту обмежує твердження, яке він підтримує.

Пряме встановлення з репозиторію потребує Node 24 у `PATH`; npm install чи збирання TypeScript не потрібні. Codex запускає нативний MCP-сервер від каталогу встановленого плагіна. Проєктні MCP-інструменти потребують явного абсолютного шляху проєкту; CLI зберігає підтримку відносних шляхів.

## Правила розгортання й браузера

Чиста підтримувана інсталяція APEX не потребує службових таблиць APEXREST. Стійка локальна історія міграцій і координація є типовими. Незалежні home чи машини потребують зовнішнього послідовного виконання або явно вибраної координації БД. Захист ідентичності, розбіжностей коду/цілі, копій, схвалення та невідомого результату залишається обов’язковим. Див. [безпеку розгортання](deployment-safety.uk.md) і [чисте розгортання APEX](clean-apex-deployment.uk.md).

Явний запит створити, оновити чи імпортувати визначений застосунок розробки/тестування дозволяє необхідний імпорт у цих межах. Production потребує захищеного зовнішнього схвалення. Робота лише із застосунком використовує відповідні перевірки; відсутній автоматизований набір ніколи не записується як успішний.

Для видимих змін застосунку навички вимагають огляду у вбудованому браузері Codex, коли доступні він і розгорнута зміна. Браузерні спостереження записуються окремо від автоматизованих тестів. Саме це правило не встановлює покриття браузерними тестами застосунку.

## Оптимізація виконання

[Локальні вимірювання](optimization-review.uk.md), [ADR 008](adr/008-runtime-optimization.uk.md) і [докази синтетичних вимірювань](evidence/optimization-local.json) покривають спільні CLI/MCP-фрагменти, відкладене завантаження інсталятора, потокові завантаження/контрольні суми й обмежене індексування довідки. Записані локальні вибірки показують менший розмір виконання, нижче пікове використання пам’яті та швидший повторний пошук. Вони не гарантують продуктивності підключеного Oracle чи інших платформ.

Середовище виконання також об’єднує свіжі читання ідентичності цілі, скидає кеш довідки компілятора при зміні інструментарію та суміщає незалежні попередні читання. Локальні регресійні фікстури покривають цю поведінку. Бар’єри запису й свіжі перевірки цілі зберігаються.

## Публічна дистрибуція

[apexrest-dev/apexrest-codex](https://github.com/apexrest-dev/apexrest-codex) — канонічний репозиторій коду. Він містить нативний marketplace і самодостатній пакет плагіна, англійську та українську документацію й дві доступні SVG-діаграми архітектури та розгортання обома мовами. Статичний сайт має 28 маршрутів, по 14 на мову, з таблицями, діаграмами, безпечним Markdown, перевіреними якорями, перемикачем мови сторінки та окремими пошуковими індексами.

[Спостереження сайту у вбудованому браузері](evidence/repository-site-browser.json) описують свій обмежений обсяг сторінок документації. `dist/releases/` містить локальні архіви, контрольні суми й звіти готовності; `site-dist/` — згенеровану документацію. Публічні пакети не містять бінарних файлів постачальників, приватного браузерного стану чи сирих локальних доказів машини.

`npm run check-release-readiness` навмисно залишається заблокованим, доки потрібні докази нативного хоста, компілятора чи повної інтеграції відсутні або застарілі. Конфігурація публікації вимкнена. Див. [наступні дії](next-actions.uk.md) щодо решти залежностей.
