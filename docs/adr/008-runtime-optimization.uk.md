# ADR 008: обмежена робота середовища виконання

[English](008-runtime-optimization.md) | Українська

Статус: реалізовано локально, 2026-09-12.

Збирайте CLI й MCP разом зі спільними ESM-фрагментами. Зберігайте кожен фрагмент безпосередньо в `runtime/`, оскільки пошук ресурсів і шляхи фонових workers відносні до `import.meta.url`. Очищуйте згенероване середовище перед перебудовою, щоб не накопичувати застарілих фрагментів. Завантажуйте setup інсталятора та його залежності валідації/клієнта лише для інсталяційних операцій. Одиниця дистрибуції — весь каталог виконання.

Потоково завантажуйте в приватні тимчасові файли з унікальними назвами. Перевіряйте наявний ліміт 512 MiB і SHA-256 під час читання потоку, потім виконуйте fsync, закриття й перейменування лише після успішної валідації. Видаляйте часткові файли за оброблених збоїв. Перед повторним використанням перевіряйте кешовані архіви свіжим потоковим хешем. Не кешуйте рішення про цілісність і не послаблюйте контроль offline/origin.

Будуйте індекс довідки при першому використанні й утримуйте лише індекс поточного файла ресурсів. Перевіряйте шлях, device, inode, розмір та наносекундні часові мітки модифікації/зміни на кожному запиті; перебудовуйте після зміни, видалення чи невдалого завантаження. Заздалегідь обчислюйте нормалізований текст пошуку й lookup за ID, зупиняйте пошук після восьми збігів. Кешуйте статичні схеми MCP-інструментів на екземпляр сервера. Ці кеші ніколи не містять ідентичності БД, відбитків розгортання, переліків коду, grants схвалення чи історії міграцій.

Індекс довідки обмінює невелику вартість першого читання й утримувану пам’ять на дешевші повторні пошуки. Спільні фрагменти потребують тестів перенесення пакета й workers. Локальні синтетичні вимірювання та обмеження записано в [огляді оптимізації](../optimization-review.uk.md); вони не встановлюють продуктивності нативного хоста чи інтеграції Oracle.
