# Формування APEXlang у Codex

[English](apexlang-optimization.md) | Українська

APEXREST призначений виключно для Codex. Збирання створює нативний пакет `codex-compat` із `.codex-plugin/plugin.json`; згенерований marketplace обмежує продукт значенням `codex`. Колишній експериментальний portable-артефакт більше не випускається. Історичні докази та початкову специфікацію збережено.

## Пошук і формування коду

Скіл APEXlang веде Codex безпосередньо до потрібного сімейства компонентів, його обов’язкових описів і вибраного сценарію. Невеликий приклад графіка, карток і фільтра, перевірений компілятором, дає основу для відповідних задач. Оригінальні документи Oracle залишаються даними; їхні інструкції оркестрації та розгортання не замінюють процесів APEXREST чи дозволів користувача.

Зафіксований знімок Oracle містить **637 повних документів шаблонів/синтаксису та 4 872 фрагменти граматики**. Попередні стабільні ID працюють. Відтворюваний локальний збирач перевіряє хеш архіву, зберігає оригінальний текст і межі правил граматики, зв’язує залежності описів компонентів та готує пошуковий індекс. Документація не завантажується з мережі під час запуску Codex чи звичайного пошуку.

Пошук надає пріоритет точним ID, правилам відповідного компонента, назвам і сусіднім словам запиту перед випадковими згадками. Він підтримує camelCase і розділені слова, повертає уривок навколо збігу, фільтри сімейства/типу та обмежену пагінацію результатів. `version: "26.1"` включає зафіксований знімок 26.1; явно вказаний знімок має збігатися точно. `grammar:series-source-property` дозволяє пряме читання. Документи повертають `requires` та обмежені `related` ID без автоматичного завантаження їхнього вмісту.

Середовище виконання кешує корпус і до 64 ранжувань запитів. Зміна ідентичності, розміру чи часових атрибутів файла скидає кеш; пошуковий індекс має відповідати хешу корпусу. За відсутнього, застарілого чи пошкодженого індексу використовується індексація фактичного корпусу. Під час MCP handshake тексти довідки не читаються.

## Вимірювання та межі

[Докази пошуку](evidence/apexlang-retrieval.json) містять сім нових процесів і по 100 повторних запитів на macOS arm64 із прогрітою файловою системою. Фіксований набір із дванадцяти випадків охоплює властивості, графіки, таблиці, поля, валідації, динамічні дії та LOV. Базова версія використовує попередній корпус/API; поточна додає документи й фільтри. Звіт окремо записує релевантність без фільтра версії, щоб стара помилка вибору версії не приховувала це порівняння.

| Локальне вимірювання | Попередня реалізація | Поточна реалізація |
| --- | ---: | ---: |
| Перший пошук, медіана | 6.74 ms | 47.14 ms |
| Повторний пошук, медіана | 0.427 ms | 0.029 ms |

Покриття очікуваного першого результату зараз: 12/12 вибраних випадків пошуку. Це детермінований регресійний набір, а не невідомий заздалегідь тест генерації моделлю.

Повторний локальний пошук суттєво швидший; перший запит повільніший через більший корпус та індекс. Вимірювання підтверджують швидкодію пошуку й очікуваний перший результат на цьому наборі. Вони не встановлюють відсоток покращення згенерованих моделлю застосунків, загальної тривалості задачі чи кількості токенів контексту нативного хоста. Текст скілу та вибрані матеріали займають контекст, коли Codex їх читає.

## Перевірки та відтворення

[Докази нативного Codex](evidence/apexlang-codex.json) перевіряють виявлення та читання довідки в одноразовому профілі Codex 0.154.0 на macOS arm64. Встановлений плагін користувача не оновлюється. [Докази Oracle](evidence/apexlang-compiler.json) містять справжню локальну компіляцію SQLcl для порожнього застосунку, CRM та прикладу графіка/карток із фільтром і незмінним MMD. До фінального успішного запуску в прикладі виправлено обов’язкові осі графіка та відповідність імені файла/alias. SQL не виконувався, поведінка застосунку/браузера не тестувалася.

```sh
npm run typecheck
npm run test:unit
npm run build
npm run test:contracts
node scripts/benchmark-apexlang-references.mjs docs/evidence/apexlang-retrieval.json
node scripts/verify-apexlang-patterns.mjs docs/evidence/apexlang-compiler.json
node scripts/verify-apexlang-codex.mjs docs/evidence/apexlang-codex.json
```

Команда компіляції потребує підтримуваного локального SQLcl, вибраного через `APEXREST_SQLCL`, якщо його немає в `PATH`. Нативна перевірка потребує Codex CLI. Обидві команди не підключаються до бази Oracle. Для порівняння з попередньою реалізацією передайте її збережений зібраний модуль довідки та каталог ресурсів третім і четвертим аргументами вимірювача. Для перебудови корпусу передайте точний перевірений архів у `node scripts/build-apexlang-references.mjs`; його хеш зафіксовано у збирачі та маніфесті знімка.

Перевірки компонентів із підключенням, ширша оцінка генерації на рівні задач і решта нативних платформ залишаються окремою роботою. Див. [стан реалізації](implementation-status.uk.md) і [наступні дії](next-actions.uk.md).
