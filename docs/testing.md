# Testing and debug workflow

For application-only page/dashboard work, use Oracle compiler validation, real read-only source-query reconciliation and Codex in-app browser checks. CRUD and utPLSQL are relevant when the change needs them. With explicit user authorization, an isolated application-only profile can declare no automated suites and record actual source/browser checks separately; preserve established profiles and failed/empty historical results. This narrow scope does not certify SQL/E2E automation or the full plugin integration matrix. See the [scope rule](../plugins/apexrest-apex/skills/apexrest-test/SKILL.md#application-only-verification-scope).

Unit tests and installer fixtures exercise logic with clearly labelled mocks; MCP contracts start the real stdio server but do not claim Oracle connectivity. `test:native-codex` installs the ZIP outside the checkout into a clean profile and checks real Codex discovery, tool calls, enable/disable and uninstall. `scripts/oracle-smoke.mjs` invokes installed SQLcl generation and validation without connecting to a DB. It records exact compiler/MMD output for both templates.

`test:integration` requires `APEXREST_INTEGRATION_PROJECT` and `APEXREST_INTEGRATION_ENV`, pre-existing named SQLcl connections, reviewed project trust, explicit test/deploy policy, an APEX 26.1+ test target and utPLSQL for its required SQL suite. Service tables are not required with default local deployment control. It refuses production and requires `APEXREST_INTEGRATION_ALLOW_WRITES=true` before apply. Missing prerequisites exit 3 and write blocked evidence; no skip is counted as integration success. Browser login must be completed locally through `test auth` with a dedicated test user.

The SQL suite executes real utPLSQL JUnit output and counts testcase elements; missing framework is dependency_missing. The CRM tests validate accepted customers, missing name, invalid email/status and duplicate email. The browser fixture creates a unique synthetic record, exercises invalid input, reads/updates/deletes that record and cleans up. Its selectors are implemented from the reviewed APEX template; live DOM verification is still required. No fake API endpoint is included. Tests configured for `api` run Playwright request tests; use the guarded testkit request helper and explicitly allow origins.

Auth state is private and expires after eight hours. Interactive login uses an ordinary browser with no recording. A successful save is not a claim that authentication works: required E2E must verify the application-specific marker and CRUD assertions. Allowed origins restrict browser traffic, including redirects; SSO/CDN origins must be explicit. The allowed-origin helper is a guardrail, not an OS network sandbox for trusted arbitrary test code.

On failure: classify dependency/authentication/source/target/test errors, read only the bounded diagnostic artifact, inspect the affected component, make one focused source fix, rerun compiler plus the affected suite, then the required gate. Stop after three unsuccessful repairs of the same cause and report evidence. Do not loosen authorization, remove required suites or replace assertions to get green.
