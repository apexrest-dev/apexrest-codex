# Інтеграція з Codex: аудит вихідного коду

[English](codex-integration.md) | Українська

Плагін призначений **виключно для Codex desktop і Codex CLI**. Шару сумісності з іншими агентськими продуктами немає. Аудит 2026-09-17 охопив справжній Rust-код OpenAI у версії `rust-v0.154.0` (`6b9826e3aa83b1a5947db50f4332cb9c65f1b340`), що відповідає локально встановленому CLI, та порівняння відповідних файлів з upstream `main` (`e269f2164cbb9f499e4f22301c393500e2a831f3`). Висновки стосуються цих ревізій, а не гарантують поведінку майбутніх версій.

## Спілкування агентів

Внутрішній механізм існує. [`AgentControl`](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/core/src/agent/control.rs#L116) підтримує спільний реєстр кореневої сесії та її дочірніх агентів. Тип і метод комунікації мають видимість `pub(crate)`. [`multi_agents.rs`](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/core/src/tools/handlers/multi_agents.rs) перетворює виклики інструментів моделлю на внутрішні операції. Ці Rust API не є RPC плагіна.

У [каталозі `ClientRequest`](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/app-server-protocol/src/protocol/common.rs#L550) є `thread/start`, `thread/resume`, `turn/start`, `turn/steer` і `turn/interrupt`; прямих викликів `agent/spawn` або `agent/send` немає. Рідні субагенти, яких обирає модель, корисні, але прохання менеджеру створювати їх не забезпечує обов’язкової послідовності рев’ю.

Тому APEXREST використовує справжній [Codex App Server](https://developers.openai.com/codex/app-server) з детермінованим контролером. Він створює окремі сесії менеджера, розробників і QA, надає обмежені командою динамічні інструменти `team_context` та `team_message`, отримує рідні події завершення. Використовуються наявний вхід у Codex і його налаштування моделі. Контролер не приєднується до поточного desktop-завдання та не запозичує його приватний реєстр агентів. Дивіться [реалізований процес](team.uk.md).

## Статуси та поверхні інтерфейсу

| Механізм | Що встановлено з коду | Наслідок для APEXREST |
| --- | --- | --- |
| Рідні повідомлення про ходи й елементи | App Server має `turn/started`, `item/completed`, `turn/completed` і події прогресу інструментів | Використовувати рідний потік для статусів виконання й рев’ю. Командний процес уже робить це. |
| Метадані MCP UI | Тести протоколу зберігають `text/html;profile=mcp-app`; елементи викликів містять URI ресурсу застосунку | Кандидат для компонента статусів у Codex desktop. Підтримка метаданих не доводить відображення у встановленому desktop. |
| `mcpServer/event/stream/start` | [Реалізація](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/app-server/src/request_processors/mcp_event_stream.rs#L47) відхиляє сервери, відмінні від hosted apps | Не використовувати як канал подій локального stdio-сервера APEXREST. |
| Маніфест плагіна | [Оголошені поля](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/plugin/src/manifest.rs#L17) охоплюють skills, MCP, apps, hooks і метадані оформлення | Схема не оголошує довільних розширень sidebar, панелей або рядка стану. |
| Рядок стану CLI | [`StatusLineItem`](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/tui/src/bottom_pane/status_line_setup.rs#L56) — фіксований Rust enum | Плагін не може додати лічильник імпорту APEX через це налаштування. Зміна enum потребує зміни коду Codex. |
| Hooks плагіна | Маніфест приймає ресурси hooks | Hooks беруть участь у підтримуваних подіях життєвого циклу; це не документований механізм малювання панелі чи прямий зовнішній API субагентів. |

[Тести можливостей MCP Apps](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/codex-mcp/src/client_capabilities_tests.rs) та [модель елемента інструмента](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/protocol/src/items.rs#L410) підтверджують висновок про метадані UI. Офіційна [документація UI](https://developers.openai.com/plugins/build/chatgpt-ui) описує зв’язування ресурсів і міст, але пояснює відображення у ChatGPT. Вона не доводить наявності fullscreen, picture-in-picture чи постійної службової панелі у Codex desktop. Досліджений репозиторій містить ядро, CLI та App Server; desktop-рендерер цей аудит не охоплював.

Поточний desktop-контекст також надає інструмент Codex `open_in_codex` для рідних панелей файлів, браузера, термінала та рев’ю. Запит показати цей дослідницький артефакт прийнято в чергу; фактичного відображення не спостерігали. Це можливість хоста, яку skill Codex може використати за наявності, а не API панелі в маніфесті плагіна. Згенерований артефакт статусів у цій рідній файловій панелі — ще один кандидат; автоматичне оновлення потребує перевірки. Консольний клієнт може показувати той самий стан через рідні результати інструментів.

## Рішення для інтеграції

Використовувати App Server Codex, сесії, sandbox, структуровані результати, динамічні інструменти та потік подій. Машина станів APEXREST відповідає за обов’язкові рев’ю та збереження статусів операцій застосунку. Наявний перемикач SQLcl CLI/MCP обирає транспорт Oracle; протокол оркестрації Codex від нього не змінюється.

[Панель розробки](panel.uk.md) тепер використовує єдиний сервіс статусів і відображається у справжньому вбудованому браузері Codex та CLI TUI. У desktop-браузері спостерігали живу роботу агентів, форми налаштувань і переходи рев’ю. Автономний MCP UI ресурс також надається; його виявлення перевіряється окремо від відображення, яке ще не підтверджено. Довільної інтеграції sidebar чи форку Codex немає.
