# Панель розробки

[English](panel.md) | Українська

Settings також містить вибір **Direct Oracle listener / ORDS HTTP(S)** і керування підключеннями рівня плагіна. Для ORDS вкажіть URL схеми, **Database username** і **Database password** наявного облікового запису Oracle Database з доступом через ORDS. Окремий обліковий запис ORDS не потрібен. Ці поля налаштовують підключення плагіна до цього облікового запису. ORDS використовує CLI. Див. [налаштування ORDS та поведінку APEXlang](ords.uk.md).

Для прямого доступу Oracle виберіть наявне збережене з’єднання SQLcl зі списку. Відкриття налаштувань Direct завантажує список; **Refresh saved connections** читає його повторно на запит. Завантаження читає локальні назви з’єднань SQLcl без підключення до бази. Поле показує стани завантаження, порожнього списку й помилки, а після невдачі — кнопку **Retry**. Наявні прив’язки залишаються доступними, навіть якщо SQLcl не повернув їх в оновленому списку. Перемикання транспорту зберігає прив’язку до прямого з’єднання й облікові дані ORDS для кожного посилання.

Режим виконання (`team` або `single`) і браузер перевірки (`codex` або `external`) обираються в налаштуваннях проєкту. Дивіться [налаштування режимів](work-modes.uk.md). Опис незалежних review/QA нижче стосується командного режиму; скріншоти від 17 вересня показують попередню версію панелі.

[Робота з APEX із чату](chat-workflow.uk.md) автоматично відкриває обрану команду; вебформа завдання необов’язкова. Картки показують причини Auto, накопичувані токени з деталізацією та ліміт часу. Кешований input і reasoning output є підмножинами, а не додатковими токенами чи оцінкою вартості.

Повний покроковий опис зі справжніми скріншотами: [агентний процес від завдання до перевіреного результату](agent-workflow.uk.md).

Відкрийте `$apexrest-panel` у Codex desktop: панель робочого простору працює у вбудованому браузері. Skill викликає `apexrest_panel_open` з абсолютним шляхом до проєкту застосунку та відкриває отриману приватну локальну адресу. Використовуйте проєкт застосунку, а не код плагіна чи його встановлений кеш. Каталог без `apexrest.json` можна переглядати, але він не може запускати розробку.

У Codex CLI:

```sh
apexrest panel tui --project /absolute/application
apexrest panel status --project /absolute/application --json
apexrest panel open --project /absolute/application --json
```

TUI використовує той самий знімок. Клавіші `1`–`4` або ліворуч/праворуч перемикають розділи, вгору/вниз або Page Up/Down прокручують, `r` оновлює, `q` завершує роботу. Після виходу стан термінала відновлюється. Для змін у консолі використовуйте CLI/MCP-операції; зображення показує desktop-панель, термінал — імена та ролі.

## Розділи й дії

| Розділ | Зафіксовані дані та доступні дії |
| --- | --- |
| Overview | Завдання, поточна фаза, стан рев’ю, режим SQLcl, зміни Git і спостережені виклики інструментів агентів |
| Agents | Окремі сесії, поточний інструмент, фактична модель/reasoning/sandbox, повідомлений обсяг токенів, повідомлення колег, рев’ю менеджера, незалежні перевірки QA, уточнення й скасування завдання |
| APEX operations | Фонові завдання та статус вкладеного результату, діагностика/посилання на артефакти, збережений стан деплою/імпорту; запуск компіляції джерел, тестів чи плану деплою з явним середовищем |
| Settings | Повна конфігурація проєкту, ідентичність середовищ і посилання на з’єднання, toolchain lock, обов’язкові набори тестів, параметри браузера/артефактів і метадані дозволів; зміна режиму SQLcl CLI/MCP та параметрів майбутніх команд |

Оновлення відбувається кожні дві секунди, доки панель видима. Список збережених з’єднань SQLcl завантажується явною дією, незалежно від цього оновлення. Поля у фокусі зберігаються. Зміни налаштувань застосовуються до майбутньої роботи; не перемикайте транспорт під час активної операції з БД. Сховища секретів для відображення не читаються. Історія обмежена дванадцятьма останніми запусками зі стислими подіями й звітами команди; оригінальні деталі залишаються в локальних записах. Токени — підсумки, повідомлені Codex, включно з вхідним контекстом, а не оцінка вартості.

`apexrest_panel_action` приймає явну дію з дозволеного переліку. Приклад CLI:

```sh
apexrest panel action --project /absolute/application --action '{"kind":"validate"}' --json
```

Підтримуються `preferences`, `sqlcl`, `connection`, `saved-connections`, `start`, `message`, `cancel-team`, `cancel-job`, `validate`, `test`, `browser`, `plan`. Дія `saved-connections` читає збережені назви з вибраної інсталяції SQLcl. Пароль ORDS приймає лише локальна браузерна форма; MCP-дії підключення не містять цього поля. Реалізація використовує обраний режим одного агента чи команди з рев’ю. Панель не може передати схвалення рев’ю, надати довіру чи безпосередньо застосувати деплой. Авторизований імпорт використовує наявний [процес деплою](deployment-safety.uk.md). Прострочений heartbeat або втрачена відповідь на зміну не означають успіх: перед повтором звірте збережений стан. Скасування не відкочує змін.

Імена сталі в межах кожної команди й показуються з ролями в панелі, терміналі, реєстрі та інструкціях агентів. Ключі ролей і далі визначають адресацію, sandbox і повноваження рев’ю. Тимчасові сесії App Server відхиляють `thread/name/set`, тому це ідентичності плагіна, а не перейменовані завдання, приєднані до поточної desktop-розмови. Аватари включені локально з [PokeAPI sprites](https://github.com/PokeAPI/sprites); ревізії джерел, хеші та upstream-повідомлення про авторські права збережені в `packages/panel/assets`. Під час роботи панель не завантажує зовнішніх зображень. Логотип APEXREST збережено.

## Інтеграція з Codex і докази

Локальний сервер слухає лише loopback, перевіряє Host/Origin, вимагає приватний ключ сесії для даних/дій та віддає фіксований перелік ресурсів. Він завершується після години без авторизованих запитів. Ключ зберігається у фрагменті URL і приватному стані проєкту; не публікуйте адресу чи файл сесії. Базові операції зберігають довіру проєкту, точні дозволи цілі/плану, резервні копії та перевірки змін. Інструменти членів команди не можуть запустити нову панель або команду.

MCP-сервер також оголошує автономний ресурс `text/html;profile=mcp-app` та документований UI-міст для хостів Codex, які його надають. Виявлення ресурсу й перевірка вмісту **не** доводять відображення вбудованого MCP UI. Перевірений desktop-шлях — справжній вбудований браузер Codex, а не довільне розширення sidebar. Форку Codex і шару сумісності з іншими агентами немає. Дивіться [аудит коду](codex-integration.uk.md).

[Докази панелі](evidence/panel-local-checks.json) відділяють локальні перевірки захисту/контрактів, спостереження у вбудованому браузері, консольні PTY-перевірки та виявлення плагіна в нативному хості. [Докази команди](evidence/panel-team-native.json) використовують справжню модель Codex на ізольованому локальному завданні з кодом. Імпорт Oracle, зміни production, робота панелі Windows чи приєднання до приватних desktop-субагентів не заявляються.

Зміна налаштувань підключення має окремі [локальні докази](evidence/connection-settings-local.json) та [докази нативного хоста](evidence/connection-settings-native.json). Записані результати визначають, які поля й виклики фактично перевірено; сама реалізація підписів і списку не підтверджує браузерного відображення чи успішного підключення до бази. Попередні докази панелі зберігають початкові межі.
