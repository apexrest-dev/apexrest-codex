# Наступні дії й точні залежності

[English](next-actions.md) | Українська

Надане лого APEXREST підключено до плагіна в репозиторії та двомовної документації. Після встановлення оновленого пакета перевірте картку плагіна, сторінку відомостей та іконку в полі запиту Codex. Відображення сайту й перевірки ресурсів пакета не підтверджують відображення в нативному інтерфейсі. Публікація залишається окремою дією, що потребує дозволу.

Локальну інсталяцію Codex оновлено й увімкнено, у її маніфесті перевірено `https://apex.rest`. Повторно відкрити сторінку відомостей плагіна й підтвердити відображене значення Website; доступ до застосунку Codex через інструмент керування комп’ютером недоступний. Почати нову задачу Codex для підхоплення встановлених навичок та інструментів. Публікація розповсюджуваної версії залишається окремою дією, що потребує дозволу.

Оптимізацію пошуку APEXlang реалізовано й локально перевірено; див. [виміряний обсяг](apexlang-optimization.uk.md). Наступний крок якості — ширший фіксований набір задач формування коду в Codex із записом спроб компіляції, часу й використаного контексту, а потім дозволені перевірки з підключенням/браузером. Дванадцять випадків пошуку та три скомпільовані композиції не замінюють оцінювання цілих задач. Єдиний цільовий продукт — Codex; роботу над випуском portable-пакета припинено.

Репозиторій надає англійську та українську документацію, доступні діаграми архітектури/розгортання обома мовами, пряме встановлення через GitHub marketplace, самодостатній нативний пакет, перевірки цілісності та міжплатформний CI. [Початок роботи](getting-started.uk.md) описує встановлення. [Стан реалізації](implementation-status.uk.md), [локальні перевірки](evidence/local-checks.json) і [докази нативного встановлення](evidence/native-repository.json) визначають фактичний обсяг і digest коду кожного запуску.

Синхронно оновлюйте обидві мови документації та виконуйте `npm run docs:check`, збирання сайту й пакувальні перевірки. Перевірки документації та браузерні спостереження сайту не оновлюють доказів Oracle чи нативного хоста.

Придатна до встановлення бета зберігає такі залежності стабільного випуску:

1. **Налаштувати окреме інтеграційне середовище з підключенням.** Визначити одноразовий застосунок і явну ідентичність БД/workspace/схеми, надати іменовані локальні з’єднання SQLcl та отримати дозвіл на конкретні зміни фікстури. Налаштувати автентифікований браузерний доступ і utPLSQL лише для відповідних SQL-наборів. Службові таблиці APEXREST не є передумовою розгортання; локальний контроль залишається типовим.
2. **Завершити матрицю фікстур із підключенням.** Перевірити export/adopt, цикли import/export без змін і зі зміненими компонентами, збереження метаданих/спільних компонентів, відхилення непідтримуваних компонентів, SQL-копію та відновлення, контрольні суми міграцій, конкуренцію runners, від’єднання/скасування й звіряння невідомого результату. Додати автентифіковані CRUD, негативну валідацію й очищення власного запуску. Сам runner успішного сценарію не засвідчує цих збоїв.
3. **Перевірити кожну нативну клієнтську платформу.** Виконати встановлення Codex і bootstrap на чистих Linux x64, Windows x64 та WSL2, оновити життєвий цикл macOS для коду випуску. Покрити відсутні залежності, відмову від ліцензії, проксі/CA, залежності браузера ОС, відсутній/пошкоджений кеш, перерваний/конкурентний setup, оновлення й збереження при видаленні. Hosted CI фікстур/пакування не замінює тестів нативного хоста. Увімкнення лише для проєкту потребує підтримуваного перевіреного механізму Codex.
4. **Завершити докази захисту й відновлення.** Перевірити збереження сторонніх плагінів, оновлення/відкат кешу між версіями, часткове встановлення та завершення дерева процесів. Перевірити зовнішньо підписане production-схвалення на захищеному runner, недоступному коду проєкту чи агента. Перевірка браузерних файлів наразі покладається на зафіксований Playwright. Очищення не доводить повного виявлення чутливих даних.
5. **Підготувати дозволений незмінний випуск.** Зібрати всі обов’язкові докази для точного digest коду випуску, налаштувати захищений CI та зовнішні облікові дані підпису/публікації, перевірити канали підтримки й необов’язкове володіння npm. Увімкнути публікацію лише для дозволеного випуску, перебудувати артефакти й пройти readiness до публікації. Бета зараз непідписана, publisher вимкнено.
6. **Необов’язкова пісочниця.** Реалізувати й перевірити законний зафіксований Linux-стек Oracle Free/APEX/ORDS/utPLSQL із дозволеним provisioning, приватними обліковими даними й постійними томами. Зберігати `supported:false` до працездатності; звичайне вимкнення має зберігати дані.

Для майбутніх видимих змін дотримуйтеся [правила вбудованого браузера](../plugins/apexrest-apex/skills/apexrest-test/SKILL.md#in-app-browser-verification). Перевіряйте змінену поведінку після завантаження й зберігайте спостереження окремо від автоматизованих результатів. Запит щодо визначеного застосунку розробки/тестування включає необхідний імпорт у цих межах; production усе ще потребує захищеного зовнішнього схвалення.

Реалізація, локальні фікстури, перевірки нативного хоста й підключена інтеграція залишаються окремими. Відсутні чи застарілі докази не можуть стати успішною умовою випуску через оновлення документації.
