# Наступні дії й точні залежності

[English](next-actions.md) | Українська

Поточне локальне мінорне оновлення — `0.2.0-beta.1`; див. [нотатки до випуску](release-notes.uk.md) та [перевірки збірки](evidence/minor-update-020.json). Після перевстановлення почніть нову задачу Codex, щоб завантажити оновлений плагін. Публікація й підтвердження стабільного випуску залишаються окремими діями; попередні докази Oracle та UI зберігають ідентичність початкової збірки.

[Налаштування підключення](panel.uk.md) пройшли [20 перевірок зібраної панелі та збереження форми у браузері Codex](evidence/connection-settings-local.json) із синтетичними обліковими даними. [Нативна перевірка](evidence/connection-settings-native.json) виявила 24 встановлені інструменти та підтвердила точну MCP-відповідь `saved-connections` за 21 справжньою локальною назвою SQLcl; публікується лише кількість. Регресійні перевірки, lint, typecheck і 45 мовних пар документації пройшли. Далі перевірте цей UI та читання сховища з’єднань у Windows/Linux. Ці перевірки не виконували спроб входу до бази й не розширюють попередні докази імпорту/експорту ORDS.

Дозволений цикл імпорту/експорту без змін через CLI [ORDS](ords.uk.md) і створення справжньої SQL-копії пройшли на приватній тестовій цілі; усі 21 повторно експортовані файли збіглися побайтово. Див. [докази з підключенням](evidence/ords-connected.json). Далі, в окремо дозволених межах тестування, перевірити імпорт зі змінами, додаткові варіанти статичних файлів/спільних компонентів/MMD, SQL-відновлення, звіряння після перерваної відповіді та Windows. Браузерну перевірку застосунку відкладено на явне прохання користувача; поточні межі — імпорт/експорт. Не розширювати зміни бази й не використовувати сторонні облікові дані заради додаткових доказів.

[Режими виконання й браузера](work-modes.uk.md) реалізовані та перевірені локально. Для оновленого встановленого плагіну почніть новий чат Codex, щоб підхопити нові інструменти та інструкції. Наступна окрема перевірка — авторизований APEX-застосунок із реальним Google/SSO входом в обраному браузері та його доступними засобами керування. Відкриття URL не доводить успішну автентифікацію чи тест; автоматизований Playwright має власний стан. Нативні Windows/Linux, embedded MCP UI та нове спостереження у браузері Codex залишаються неперевіреними.

[Роботу з чату й моделі Auto](chat-workflow.uk.md) реалізовано. Розширити перевірку на автоматичний вибір скіла в нових desktop/CLI чатах, відновлення перерваного хоста, варіанти недоступного каталогу та порівняння токенів/затримки на однакових завданнях. Зберегти обов’язкові незалежні рев’ю й відрізняти накопичуваний кешований input від вартості. Поточне нативне виконання та спостереження панелі описані у стані реалізації.

[Агентний посібник зі скріншотами](agent-workflow.uk.md) завершено обома мовами: чотири справжні кадри панелі й схема процесу. Оновлюйте зображення при зміні UI або процесу; зберігайте підписи про ізольоване локальне завдання з кодом. Командна робота з підключеним Oracle, вбудоване MCP UI та перевірка Windows залишаються окремими відкритими пунктами.

[Обов’язкову команду](team.uk.md) та [панель розробки](panel.uk.md) реалізовано. Розширити перевірку на авторизовані завдання APEX, QA-набори із записом артефактів, консоль/відновлення процесів Windows та вбудоване відображення MCP UI. Відображення у вбудованому браузері та справжні сесії App Server — окремі докази від довільного desktop-sidebar або приєднання дочірніх сесій. [Аудит коду](codex-integration.uk.md) описує фактичні точки інтеграції. Після зміни джерел оновлювати встановлений bundle через CLI; нові skills/інструменти підхоплюються в новому завданні Codex.

Вибір SQLcl CLI / офіційного MCP реалізовано й перевірено локально, зокрема в псевдотерміналі macOS та реальному SQLcl офлайн. Далі потрібні дозволені перевірки запитів, експорту, імпорту, меж транзакцій і звірки невідомого результату в обох режимах на визначеній цілі розробки/тестування. Окремо перевірити аудит Oracle MCP і Windows. Перевірки з підключенням і нативним хостом залишаються відкритими; див. [реалізацію та докази](implementation-status.uk.md#sqlcl-cli--офіційний-sqlcl-mcp--2026-09-16).

[Огляд навичок 2026-09-16](evidence/skill-review-local.json) не виявив підтверджених дефектів інструкцій. Наступною перевіркою якості навичок залишається фіксований набір повних задач формування коду з подальшими дозволеними перевірками SQL/імпорту з підключенням і браузера; успішні локальні перевірки пошуку, пакування й офлайн-компіляції не закривають ці прогалини.

Користувач дозволив публікацію в npm. Бета-архів підготовлено, встановлення його CLI перевірено. Виконайте вхід у npm обліковим записом із правами на `@apexrest`, перевірте доступ до області, опублікуйте перевірений архів із публічним доступом і тегом `beta`, потім перевірте метадані реєстру та встановлення з реєстру. Публікацію наразі блокує `ENEEDAUTH`. Застарілу локальну реєстрацію маркетплейсу Codex виправлено для перевіреного пакета панелі, як зафіксовано нижче.

[Панель APEXlang у TUI](tui.uk.md#панель-apexlang) реалізовано й перевірено локально: комплектний каталог, пошук, прокручування, перемикання фокуса та адаптивна таблиця. Далі перевірте термінали macOS/Windows. Кількість документованих типів не підтверджує роботу всіх варіантів компілятора; для цього зберігайте окремі фактичні докази Oracle. Див. [локальний звіт](evidence/tui-apexlang-dashboard-local.json).

Документацію встановлення оновлено в [README](../README.uk.md), [посібнику початку роботи](getting-started.uk.md#встановлення-через-термінал) і [сторінці встановлення сайту](../site/content/install.uk.md). [Локальна перевірка](evidence/installation-documentation-local.json) стосується документації та згенерованого сайту. Далі перевірте описаний процес у нових середовищах підтримуваних платформ; сам перегляд тексту не закриває реальних нативних або Oracle-перевірок.

[Оновлення наявної локальної реєстрації](implementation-status.uk.md#наявна-локальна-реєстрація-плагіна) усуває повідомлений конфлікт належності для виділеного локального marketplace APEXREST без керованого запису. [Докази реєстрації](evidence/setup-registration-local.json) фіксують успішні локальні перевірки, ізольоване нативне перенесення/повторний Setup і дозволене виправлення в поточному профілі користувача. Файли кешу й MCP перевірено; попереднє джерело, сторонні реєстрації/налаштування та наявний інструментарій збережено без завантажень чи роботи з Oracle. Далі завершіть перевірки macOS/Windows і матриці реальних нативних збоїв, відновлення після невідомих результатів та координації між машинами.

Скорочений [TUI](tui.uk.md) має лише встановлення/видалення інструментів і плагіна та список/перевірку збережених з’єднань SQLcl і вибір SQLcl CLI/MCP. Поточний потік виконує дію після Enter на перегляді без перемикачів Preview only або Approve changes; див. [перевірку прямого виконання](evidence/tui-direct-run-local.json). [Докази](evidence/tui-focused-local.json) розділяють локальні тести, термінал Linux і реальне читання порожнього сховища SQLcl. Далі перевірте з’єднання з чинними збереженими обліковими даними та термінали macOS/Windows. Відповіді SQLcl у термінальних фікстурах не є доказом з’єднання Oracle.

[Виправлення вибору джерела Setup](implementation-status.uk.md#вибір-джерела-setup) обмежує встановлення вибраним плагіном і зберігає відхилення символічних посилань усередині цього пакета. Історичні [локальні докази](evidence/setup-source-local.json) фіксують успішні регресійні контракти, фікстури інсталятора із заглушкою Codex і попередні перегляди в CLI/терміналі Linux без нативного встановлення чи запису конфігурації Codex. Пізніші перевірки нативної реєстрації зафіксовано окремо вище. Поведінку вибору джерела на macOS/Windows ще належить перевірити; попередні фікстури не підтверджують поведінку нативного хоста чи Oracle.

Навичка **All functions** показує меню APEXREST у розмові після запиту `Use $apexrest-menu`; вона не додає постійну кнопку в бічну панель або верхнє меню. Дослідження відсутнього меню 2026-09-13 підтвердило, що плагін встановлено й увімкнено, усі десять навичок доступні в активній розмові, а діагностичний MCP-інструмент відповідає. Далі підтвердьте, що користувач може відкрити меню в розмові, та перевірте його пошук через настільний вибір `@` або **Plugins → Installed**. Нативне візуальне відображення та причина повідомлення про відсутній пункт залишаються неперевіреними; саме лише виявлення хостом не розв’язує цю проблему. Див. [навігацію меню](getting-started.uk.md#усі-функції-в-меню-плагіна-codex). Встановлення для розробки використовує перевірений локальний пакет і не потребує публікації цих інструкцій.

Команду плагіна **Install dependencies** реалізовано й додано до пакета; після встановлення оновленого пакета викличте `$apexrest-install-dependencies`. Нативне виявлення перевірено в ізольованому профілі Linux. Далі перевірте відображення меню команди в застосунку Codex і виконайте дозволені реальні завантаження залежностей, відмову від ліцензії та обробку системних залежностей браузера на чистих підтримуваних платформах. Ця зміна не оновлює докази інтеграції Oracle й не встановлює залежностей у звичайне середовище користувача. Див. [перевірку команди](implementation-status.uk.md#команда-встановлення-залежностей).

Прозорий символ APEXREST без напису підключено до плагіна в репозиторії та двомовної документації. Після встановлення оновленого пакета перевірте картку плагіна, сторінку відомостей та іконку в полі запиту Codex. Відображення сайту й перевірки ресурсів пакета не підтверджують відображення в нативному інтерфейсі. Публікація залишається окремою дією, що потребує дозволу.

Локальний плагін Codex і глобальний CLI тепер використовують перевірений bundle панелі; застарілий шлях marketplace виправлено. Відкрийте нове завдання Codex, щоб підхопити дванадцять skills і двадцять один інструмент. Відображення картки плагіна, composer icon і поля Website в межах перевірки панелі повторно не перевіряли. Публікація дистрибутива залишається окремою авторизованою дією.

Оптимізацію пошуку APEXlang реалізовано й локально перевірено; див. [виміряний обсяг](apexlang-optimization.uk.md). Наступний крок якості — ширший фіксований набір задач формування коду в Codex із записом спроб компіляції, часу й використаного контексту, а потім дозволені перевірки з підключенням/браузером. Дванадцять випадків пошуку та три скомпільовані композиції не замінюють оцінювання цілих задач. Єдиний цільовий продукт — Codex; роботу над випуском portable-пакета припинено.

Репозиторій надає англійську та українську документацію, доступні діаграми архітектури/розгортання обома мовами, пряме встановлення через GitHub marketplace, самодостатній нативний пакет, перевірки цілісності та міжплатформний CI. [Початок роботи](getting-started.uk.md) описує встановлення. [Стан реалізації](implementation-status.uk.md), [локальні перевірки](evidence/local-checks.json) і [докази нативного встановлення](evidence/native-repository.json) визначають фактичний обсяг і digest коду кожного запуску.

Синхронно оновлюйте обидві мови документації та виконуйте `npm run docs:check`, збирання сайту й пакувальні перевірки. Перевірки документації та браузерні спостереження сайту не оновлюють доказів Oracle чи нативного хоста.

Придатна до встановлення бета зберігає такі залежності стабільного випуску:

1. **Налаштувати окреме інтеграційне середовище з підключенням.** Визначити одноразовий застосунок і явну ідентичність БД/workspace/схеми, надати іменовані локальні з’єднання SQLcl та отримати дозвіл на конкретні зміни фікстури. Налаштувати автентифікований браузерний доступ і utPLSQL лише для відповідних SQL-наборів. Службові таблиці APEXREST не є передумовою розгортання; локальний контроль залишається типовим.
2. **Завершити матрицю фікстур із підключенням.** Перевірити export/adopt, цикли import/export без змін і зі зміненими компонентами, збереження метаданих/спільних компонентів, відхилення непідтримуваних компонентів, SQL-копію та відновлення, контрольні суми міграцій, конкуренцію runners, від’єднання/скасування й звіряння невідомого результату. Додати автентифіковані CRUD, негативну валідацію й очищення власного запуску. Сам runner успішного сценарію не засвідчує цих збоїв.
3. **Перевірити кожну нативну клієнтську платформу.** Виконати встановлення Codex і bootstrap на чистих Linux x64, Windows x64 та WSL2, оновити життєвий цикл macOS для коду випуску. Покрити відсутні залежності, відмову від ліцензії, проксі/CA, залежності браузера ОС, відсутній/пошкоджений кеш, перерваний/конкурентний setup, оновлення й збереження при видаленні. Hosted CI фікстур/пакування не замінює тестів нативного хоста. Увімкнення лише для проєкту потребує підтримуваного перевіреного механізму Codex.
4. **Завершити докази захисту й відновлення.** Перевірити збереження сторонніх плагінів, оновлення/відкат кешу між версіями, часткове встановлення та завершення дерева процесів. Перевірити зовнішньо підписане production-схвалення на захищеному runner, недоступному коду проєкту чи агента. Перевірка браузерних файлів наразі покладається на зафіксований Playwright. Очищення не доводить повного виявлення чутливих даних.
5. **Підготувати дозволений незмінний випуск.** Зібрати всі обов’язкові докази для точного digest коду випуску, налаштувати захищений CI та зовнішні облікові дані підпису/публікації, перевірити канали підтримки й необов’язкове володіння npm. Увімкнути публікацію лише для дозволеного випуску, перебудувати артефакти й пройти readiness до публікації. Бета зараз непідписана, publisher вимкнено.
6. **Необов’язкова пісочниця.** Реалізувати й перевірити законний зафіксований Linux-стек Oracle Free/APEX/ORDS/utPLSQL із дозволеним provisioning, приватними обліковими даними й постійними томами. Зберігати `supported:false` до працездатності; звичайне вимкнення має зберігати дані.

Для майбутніх видимих змін дотримуйтеся [правила вбудованого браузера](../plugins/apexrest-apex/skills/apexrest-test/SKILL.md#in-app-browser-verification). Перевіряйте змінену поведінку після завантаження й зберігайте спостереження окремо від автоматизованих результатів. Запит щодо визначеного застосунку розробки/тестування включає необхідний імпорт у цих межах; production усе ще потребує захищеного зовнішнього схвалення.

Реалізація, локальні фікстури, перевірки нативного хоста й підключена інтеграція залишаються окремими. Відсутні чи застарілі докази не можуть стати успішною умовою випуску через оновлення документації.
