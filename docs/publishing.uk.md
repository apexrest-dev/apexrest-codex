# Налаштування публікації

[English](publishing.md) | Українська

Користувач вибрав [apexrest-dev/apexrest-codex](https://github.com/apexrest-dev/apexrest-codex) репозиторієм коду. Git origin і `publisher.config.json.githubRepository` використовують його. Коміти й push коду дозволені; publisher випуску залишається вимкненим. Ця конфігурація репозиторію не створює GitHub release, тег, npm-пакет і не змінює сайт, DNS чи TLS.

До публікації власник має створити захищене release environment і зовнішньо керований ключ підпису, перевірити ліцензії Node/Java/SQLcl/браузера, виконати справжні тести нативного хоста для кожної платформи та завершити докази Oracle/utPLSQL/CRUD для точного незмінного коміту. Налаштуйте GitHub private vulnerability reporting і перевірений контакт безпеки. npm необов’язковий і потребує перевірки володіння `apexrest`.

`release:dry-run` завжди записує відтворювані локальні ZIP, контрольні суми, CycloneDX SBOM, походження, точні локальні команди встановлення та release-readiness.json. Збірки з незакоміченими змінами/без коміту мають digest дерева коду й не можуть бути стабільними. Manifest можна підписати лише явно наданим зовнішнім `APEXREST_RELEASE_SIGNING_KEY_FILE`. Перевірка bootstrap публічним ключем необов’язкова для локально вибраного користувачем SHA; майбутній віддалений канал має вимагати довірений підпис. Непідписані локальні бета-файли не подаються як опубліковані випуски.

Захищений процес випуску ручний і використовує protected environment. Stable readiness блокує випуск за відсутніх, застарілих або отриманих з іншого коду обов’язкових доказів. Конфігурацію publisher також слід увімкнути. Копіюйте лише `site-dist/` під наявний шлях `/codex/` через `scripts/publish-site.sh --dry-run DEST`; фактичне копіювання потребує явного `--apply` та змонтованого дозволеного місця призначення. Не змінюйте кореневої головної сторінки. GitHub-артефакти залишаються незмінним джерелом; інсталятори/метадані сайту генеруються з того самого release manifest.

Подання в каталог OpenAI — окремий ручний процес. Підготуйте ідентичність/автора, ліцензію, обробку даних, підтримку й докази нативної сумісності. Прийняття в публічний каталог не гарантоване й не потрібне для локального нативного встановлення.
