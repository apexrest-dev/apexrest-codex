# Встановлення APEXREST

[English](install.md) | Українська

Встановіть CLI APEXREST через npm, відкрийте його термінальне меню, встановіть клієнтські інструменти й плагін Codex, потім перевірте збережене з’єднання SQLcl. Пакет npm містить готову збірку; звичайне встановлення не потребує збирання TypeScript.

## 1. Відкрийте термінальне меню

Використовуйте Node.js 24 LTS у PATH (підтримуваний діапазон: Node 24–26). Для встановлення плагіна також потрібен Codex CLI з підтримкою нативних плагінів.

```sh
npm install -g apexrest
apexrest --version
apexrest
```

Стандартний тег npm — `latest`. Щоб зафіксувати випуск 1.2.0, використовуйте `npm install -g apexrest@1.2.0`. Стан розповсюдження й перевірок — у [примітках до випуску](../../docs/release-notes.uk.md).

Для локального встановлення CLI у проєкті виконайте ці команди з каталогу проєкту:

```sh
npm install apexrest
npx apexrest --version
npx apexrest
```

npm встановлює CLI й комплектні ресурси. Окремо зареєструйте плагін Codex через **Install plugin** на кроці 2; локальне встановлення npm у проєкті не створює реєстрації плагіна Codex лише для цього проєкту.

Альтернативно використовуйте Git, щоб відкрити готовий CLI з [репозиторію коду](https://github.com/apexrest-dev/apexrest-codex):

```sh
git clone https://github.com/apexrest-dev/apexrest-codex.git
cd apexrest-codex
node plugins/apexrest-apex/runtime/apexrest.mjs
```

Якщо копія репозиторію вже є, виконайте останню команду в ній. Усі способи відкривають те саме меню. Логотип APEXREST відкривається разом із сімома діями: **Install tools**, **Uninstall tools**, **Install plugin**, **Uninstall plugin**, **List saved SQLcl connections** і **Test saved SQLcl connection**.

Вибір **SQLcl mode: CLI / MCP** зберігає спосіб виконання Oracle-команд: SQLcl CLI або офіційний SQLcl MCP (`sql -mcp`). Це окрема дія TUI; вона не змінює реєстрацію плагіна. Див. [режими SQLcl](../../docs/tui.uk.md#режим-sqlcl-cli-або-mcp).

На головному екрані також є таблиця типів APEXlang із комплектного довідника Oracle. Tab перемикає дії й каталог; вводьте назву або групу для пошуку. Для перегляду з’єднання з базою не потрібне.

## 2. Встановіть інструменти й плагін

Виберіть **Install tools**. Прочитайте [умови Oracle](https://www.oracle.com/downloads/licenses/oracle-free-license.html) і увімкніть **Accept Oracle license terms**, якщо погоджуєтеся. Параметр **Skip browser installation** дозволяє пропустити Playwright і Chromium; дозвіл системних пакетів браузера задається окремо в додаткових параметрах. Ctrl+R відкриває **Review**, Enter встановлює.

Потім виберіть **Install plugin** й натисніть Enter на **Review**. Дія використовує наявне середовище виконання. Через Esc і Ctrl+O можна вибрати інший профіль Codex, джерело пакета або керований каталог. Якщо змінювали каталог інструментів, використовуйте його і для плагіна.

Перемикачів **Preview only** і **Approve changes** у TUI немає: Enter на перегляді виконує дію. Прочитайте фактичний результат і незавершені кроки. Перезапустіть Codex та почніть нову задачу після реєстрації.

## 3. Додайте засіб запуску

Глобальне встановлення npm уже надає команду `apexrest`; пропустіть цей крок, якщо вона доступна. Для локального встановлення npm у проєкті використовуйте `npx apexrest` із цього проєкту. Кероване встановлення плагіна також створює засіб запуску. Щоб використати його зі стандартного каталогу на macOS/Linux:

```sh
export PATH="$HOME/.apexrest/bin:$PATH"
apexrest
```

У PowerShell:

```powershell
& "$env:USERPROFILE\.apexrest\bin\apexrest.ps1"
```

Для нестандартного керованого каталогу використовуйте його `bin`. Налаштування постійного PATH і запуск без керованого встановлення описано в [посібнику CLI](../../docs/getting-started.uk.md#використання-cli). Саме встановлення інструментів або пряма реєстрація через Codex не створює цього засобу запуску.

## 4. Перевірте збережене з’єднання SQLcl

Відкрийте **List saved SQLcl connections** або **Test saved SQLcl connection**. Вводьте текст для пошуку, виберіть назву та натисніть Enter для перевірки. Ctrl+R оновлює список. Псевдонім APEXREST не потрібен; відсутні з’єднання й облікові дані зберігаються в SQLcl. Паролі в TUI не вводяться.

```sh
apexrest connection list --saved --json
apexrest connection test 'Development connection' --saved --json
```

Замініть назву на точну назву свого з’єднання. Для роботи із застосунком також налаштуйте явне середовище проєкту за [посібником](../../docs/getting-started.uk.md#підключення-й-налаштування). Успішне встановлення плагіна саме по собі не підтверджує доступ до бази даних.

## Пряме встановлення через Codex CLI

Для реєстрації готового плагіна без копії репозиторію використовуйте Node 24 у PATH та виконайте:

```sh
codex plugin marketplace add apexrest-dev/apexrest-codex
codex plugin add apexrest-apex@apexrest
codex plugin list --json
```

Цей спосіб не створює команду `apexrest` в оболонці. У новій задачі Codex надішліть `Use $apexrest-menu` для всіх робочих дій або скористайтеся `$apexrest-install-dependencies` для залежностей. Меню навички в розмові та явний CLI зберігають свої додаткові параметри; сім дій TUI описано вище. [Посібник встановлення плагіна](../../docs/getting-started.uk.md#встановлення-плагіна) містить перевірки й навігацію.

## Codex Cloud

Для хмарної задачі з репозиторієм скористайтеся [посібником налаштування Cloud](../../docs/codex-cloud.uk.md). Скопіюйте скрипти прикладу до репозиторію застосунку, налаштуйте середовище та Secret і використовуйте CLI-засіб запуску для операцій ORDS HTTPS. Приклад не встановлює desktop-інтерфейс і не перевіряє нативне виявлення MCP у Cloud.

## Видалення

У TUI виберіть **Uninstall tools** або **Uninstall plugin**, перегляньте дію й натисніть Enter. Якщо видаляєте обидва компоненти, спершу видаліть інструменти: видалення файлів плагіна прибирає код, на який посилається керований засіб запуску. **Keep plugin files** зберігає цей код після скасування реєстрації.

Проєкти, резервні копії, збережені з’єднання, кеш і зовнішні середовища виконання зберігаються. Node.js для засобу запуску або записаного встановлення також залишається. Пряме встановлення через Codex видаляється командами Codex, наведеними в [посібнику видалення](../../docs/getting-started.uk.md#видалення-плагіна-з-репозиторію).

Щоб видалити глобально встановлений npm CLI після потрібного видалення інструментів/плагіна:

```sh
npm uninstall -g apexrest
```

Для локального встановлення в проєкті виконайте `npm uninstall apexrest` із цього проєкту. Видалення через npm не скасовує реєстрацію плагіна Codex і не видаляє керовані інструменти; це окремі дії, описані вище.

## Збирання й обсяг перевірки

Для розробки плагіна або відтворюваного пакування з копії репозиторію:

```sh
npm ci --ignore-scripts
npm run plugin:sync
npm run site:build
npm run release:dry-run
```

`dist/releases/install-local.txt` містить згенеровані локальні хеші пакетів і Bash/PowerShell-команди встановлення. Пакування не публікує випуск. [Стан реалізації](../../docs/implementation-status.uk.md) відокремлює термінальні перевірки Linux, локальні фікстури та попередні нативні перевірки від непідтверджених реальних з’єднань і решти платформ. Інші робочі дії APEX залишаються в плагіні та явному CLI.
